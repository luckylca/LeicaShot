## Pipeline and ownership observations

The reference engine sequences color, depth, bokeh, and optional subject protection in one engine, with a separate GAIC composition path. It normalizes photo orientation before mapping user points and caps analysis dimensions independently from export dimensions. A depth estimate is relative depth rather than calibrated metric distance. The color model predicts low-frequency color and the original detail is restored through Lab fusion. For bokeh, the pipeline derives a circle-of-confusion field from relative depth, focus, and aperture, then invokes ARNet at multiple blur scales and separately handles highlights and subject edges.

Subject protection reuses a prepared SAM image-input array across prompt points, selects among mask candidates, creates a trimap, and runs ViTMatte on unknown-boundary areas. The inspected reference still passes that image tensor through the SAM graph for each new point; it caches completed per-point alpha results for incremental edits, not the encoder embedding. It releases SAM before loading ViTMatte. Its large-image matting uses 1024-square tiles, up to 768-pixel steps, and feathered overlap; this is explicitly a memory/consistency tradeoff, not a guarantee of full-frame numerical equality. GAIC proposes/scored crops separately from final export and maintains original-image coordinate mapping.

The reference code includes separate edge and highlight modules (including `SoftBokehEdges`, `BokehRadiance`, `ClippedHighlights`, `HighlightExtraction`, `HighlightScatter`, `NaturalSubjectEdges`, `GradientSubjectEdges`, and `SharpSubjectEdges`). These are distinct from the learned ARNet pass and must be measured/tested as a group if implemented in Laika. Its regression suite includes synthetic math, image fixtures, edge, matte-tile, composition, cancellation, and workflow tests; a JVM test pass cannot validate ONNX model execution or service memory.

## Math and coordinate details found in source

- **Orientation and coordinates:** the source reads EXIF orientation and transposes pixels before model coordinates are used. Focus and protection points are normalized to `[0,1]` in the oriented full image; SAM scales them to its fixed 1024 coordinate frame. GAIC boxes are expressed in the resized analysis image's pixels and mapped crop suggestions remain relative to the original oriented image.
- **Color fusion:** M9 input is RGB with `((byte / 255) - 0.5) / 0.5`. The output is mapped back to RGB. Fusion transforms original and predicted RGB to 8-bit Lab and, independently per channel, computes `original + Gaussian(predicted - original)`, using sigma 25 for L and 20 for a/b. This is the reference's high-frequency detail restoration; it is not simple RGB blending.
- **Depth postprocessing:** raw depth is relative, not metres. The reference sorts the output, uses the 2nd and 98th percentiles as low/high bounds, then clips and maps to `[0,1]`. Focus is sampled from a small neighborhood around the selected point; a point near a depth edge can be rejected instead of silently selecting an unstable plane.
- **Defocus:** the reference uses a synthetic thin-lens scale (50 mm focal length, 36×24 mm sensor, discrete f-number choices) and maps normalized relative depth through a virtual inverse-distance range of 1.2–30 m. Per-pixel CoC is `(depth - focus) * radiusScale`, resized bilinearly to the render size. The docs correctly state this is not camera calibration.
- **ARNet multiscale:** RGB is area-downsampled; CoC is resized, divided by the current scale and 10, then clipped to `[-1,1]`. The sequence grows from full size by powers of two up to a scale derived from maximum CoC; larger-blur bands blend over earlier passes. The full output canvas is still preserved.
- **Highlights and edges:** highlights are separated in linear light from a base image, boosted and optically scattered on a highlight-specific path; clipped-light recovery, a soft disc edge/shoulder, clean background-plate filling, foreground/alpha safeguards, and edge decontamination run around the final composite. These are CPU/native math stages and need separate timing and memory measurements from ARNet.
- **Subject encoder reuse and input geometry:** reference alpha caching is per completed prompt point, so removing/reordering points can reuse refined alpha mattes. Each missing point passes the same 1024-square image tensor to a combined SAM graph, rerunning image encoding. Laika's adapter separates encoder and decoder sessions and caches the exact encoder outputs under a byte-bounded LRU. Its RGB preparer follows the reference's separable antialias filter and width-then-height resize order; normalized oriented-image prompts map directly to the 1024 model frame. Synthetic geometry tests compare against scalar implementations of the inspected filter and half-pixel bilinear sampling. Candidate selection uses descending scores, rejects masks that miss the positive click, restores the chosen logits to the subject-analysis dimensions, then thresholds at zero. The trimap uses the reference's 5-pixel radius at 1220 and ellipsoidal erosion/unknown-band logic with neutral outside-image boundaries. The adapter passed checkpoint-backed tensor parity; real-photo mask quality remains unmeasured. The 2 GiB single-stage measurements are recorded in the [SAM benchmark](../benchmarks/m1-sam2-cgroup-2026-10-21.md).
- **Attention scope:** the reference `ChunkAttention` conversion is used for Depth Anything V2 and preserves full-key global attention. The inspected ViTMatte path lowers its peak through selective overlapping tiles; it does not use the reference's chunk-attention adapter. Laika should test Q chunking/streaming softmax for ViTMatte separately and prove the exported ONNX graph keeps the intended memory behavior.

Model names alone are insufficient provenance. Before any model adapter is implemented, pin the source revision and checkpoint hash, record exact preprocessing and tensor names/shapes, reproduce conversion, compare framework and ONNX outputs, and preserve runtime hash checks.

## Initial low-memory hypotheses to measure

1. **Query-chunked exact global attention:** the reference export script chunks Q and attends each chunk to the complete K/V set. This bounds the materialized score matrix by chunk size while preserving global key coverage. Verify the exported graph does not re-materialize the full matrix and compare output error for chunk sizes 16/32/64/128.
2. **ViTMatte tiling:** reference tiles are 1024×1024, overlapping and feathered. Compare 512/768/1024 tiles only with a fixed full-frame or trusted reference output, including hair and boundary seam cases; preserve full analysis resolution.
3. **Sequential session lifetime:** the reference closes SAM before ViTMatte. Measure model load, inference, release, process RSS/USS, and cold/hot latency. Process exit may release native allocations more reliably, but can increase cold-start time.
4. **Feature reuse:** for multiple SAM clicks on the same image, cache image embeddings once and reuse them in the mask decoder. Bound cache size and invalidate on image identity/transform changes.
5. **Buffers and data movement:** quantify image decode, tensor conversion, copies, and postprocessing separately. Avoid keeping multiple full-resolution float RGB arrays alive; use byte planes, preallocation, row/tile transforms, or disk-backed intermediates only when measurements show a benefit.

These remain experiments. SAM now has a constrained single-stage result, and earlier depth reports include constrained single-stage trials. No 8GB, 4GB, or 2GB complete-pipeline target has been demonstrated.
