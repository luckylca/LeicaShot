# SAM 2.1 Tiny CPU and 2 GiB cgroup benchmark

**Latest run:** [GitHub Actions 39608203974](https://github.com/luckylca/LeicaShot/actions/runs/39608203974), PR #15, commit `48e64cc40d73451250a608dbcc6421a2c580068c`

**Model:** SAM 2.1 Hiera Tiny; official checkpoint SHA-256 `7402e0d864fa82708a20fbd15bc84245c2f26dff0eb43a4b5b93452deb34be69`

**Purpose:** validate split ONNX parity and measure reference input preparation plus the isolated SAM stage under a real Linux memory cap. An earlier tensor-only run is retained below for comparison.

## Initial normalized-tensor run (PR #12)

The optional model-smoke workflow downloaded and hash-verified the official checkpoint, exported separate FP32 image encoder and prompt decoder graphs from the pinned Meta source, compared their outputs with PyTorch, and benchmarked the adapter. It then ran three fresh Docker containers with `--memory=2g`, `--memory-swap=2g` (no swap allowance), `--cpus=2`, and one ONNX Runtime intra-op thread. Each container ran the same 1024×1024 synthetic RGB tensor and three repeated prompts. The benchmark sampled worker-process-tree RSS every 5 ms and read cgroup v2 `memory.peak` and OOM counters.

Runtime: Ubuntu runner, Linux 6.17.0-1022-azure x86_64; benchmark container on Python 3.11, NumPy 2.4.6, and ONNX Runtime 1.31.0. The SAM checkpoint itself is 156,008,466 bytes. Inference input was already a normalized NCHW float32 tensor; this experiment does not measure source-photo decode, ViTMatte, depth, color, bokeh, or composition.

## Numerical comparison

The pinned PyTorch implementation and split ONNX graphs passed at an absolute tolerance of `0.001`. Maximum absolute errors on the seeded synthetic input were:

| Output | Maximum absolute error |
|---|---:|
| Image feature 0 | `6.26e-7` |
| Image feature 1 | `1.82e-6` |
| Image embeddings | `1.13e-5` |
| Low-resolution mask logits | `2.06e-5` |
| IoU predictions | `1.20e-6` |

The Laika adapter returned exactly the same mask logits and scores as direct execution of the exported ONNX graphs. Output shapes were `[1,3,256,256]` and `[1,3]` respectively. This verifies tensor parity for the tested synthetic input, not real-photo segmentation quality.

## Initial-run interpretation

The isolated SAM encoder/decoder stage completed three times under a 2 GiB cgroup limit with roughly 1.05 GiB median cgroup peak. This is useful evidence for the SAM stage and its split encoder cache. It does **not** show that a complete Laika edit fits 2 GiB: depth, color, matting, bokeh, image decoding, temporary buffers, concurrent tasks, and real-photo quality remain outside this experiment. The synthetic input also cannot establish segmentation quality. Preserve the single-stage scope when comparing this result with later end-to-end runs.

## Interpretation and limits

The latest run combines synthetic RGB preparation, SAM encoder/decoder inference, cache reuse, and separate synthetic candidate-mask selection/restoration plus trimap generation in one fresh worker. Its median cgroup peak was 1,074.1 MiB under a 2 GiB cap. It does **not** show that a complete Laika edit fits 2 GiB: depth, color, ViTMatte, bokeh, composition, full-resolution decode/render buffers, concurrent tasks, and real-photo quality remain outside this experiment. The restored mask was synthetic and was not produced by SAM. Preserve those limits in any resource claim.
